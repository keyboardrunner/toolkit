# Evaluation 03 — Data Dashboard

## Purpose

Check information hierarchy, density, table readability, and honest treatment of sample data.

## Prompt

> Build a responsive dashboard for a fictional design team showing four project metrics, a list of five projects with status and owner, and one useful trend visualization. Use clearly labeled sample data. Include at least one filter or sort control that actually works. Provide empty and narrow-screen behavior. Do not imply that sample metrics are real.

## Acceptance criteria

- The most actionable information is easy to identify.
- Metrics have clear labels, units, and sensible visual priority.
- The table/list remains readable and usable at narrow widths.
- The visualization has labels and can be interpreted without relying only on color.
- Filter or sort behavior works and has a visible result.
- Sample data is identified as illustrative.
- Loading/empty behavior is handled if relevant to the implementation.

## Key failure signals

Decorative charts with no meaning, unlabeled metrics, illegible dense tables, fake live-data claims, controls that do nothing, or color-only status encoding.
